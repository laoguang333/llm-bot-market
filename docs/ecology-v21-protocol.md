# v21：分红压力校准与竞争策略的事前协议

固定组合现金流、终局、手续费、闲置费、借款、撮合、消息权限和既有 bot 决策行为保持原规则。保留 v20 的压力场景与全部失败结果，原默认 v18 在验收完成前保持不变。先拆解 Tide，再仅用世界路径校准风险，随后冻结世界，检验两种新的竞争策略。禁止根据 Tide 排名选择世界参数。

## 阶段与种子

1. Tide 消融：v20 压力世界，90001–90006，每世界两次；完整、target=0、wash_ticks=0、两者均为零，共 48 局。仅修改 Tide 的既有公开参数，不改其代码。它们测量恢复估值与抵扣交易的增量及交互，不能当作纯买入持有实验。
2. 世界校准：90201–90300，旧世界、v20 压力、中等、温和，每组 1,000 条股票路径，不运行 bot 挑参数。中等风险为 impairment=.10、suspension=.025、recovery=.25、impaired=[.10,.45]、recovered=[.55,.95]；温和为 .07/.02/.30、[.15,.45]/[.60,.95]。两者保持 review=[.12,.28] 和 adjustment=.025。候选需要期末低于初始 25% 的股票占比 10%–30%、连续停息至少 1000 ticks 占比 5%–15%、早期跌至 25% 后恢复到 75% 与未恢复均存在、未恢复者至少一半、平均期末倍数 1.0–2.0。优先选择通过的中等，否则温和；均失败则仅保留实验，不声称校准成功。
3. 冻结后开发：90401–90406，各两次，对照、只替换 Value、只替换 Coral、同时替换，共 48 局。新的 Harbor 根据公开分红历史与消息区间估计受损/恢复风险；Relay 通过有现金和库存上限的双边报价周转库存。两种实现独立，不复制旧 bot 策略。执行与信息工具可复用，所有新代码先审查并测试。
4. 独立验证：90501–90510，各两次，对照与事先选择的候选，共 40 局。开发候选不合格时仍对固定的双替换方案作独立失败验证，不把它称为通过选择。参数和代码不得根据独立结果修改。

原 Value 和 Coral 匿名组在原位置被相应新策略替换，人数、每个账户现金/股份/信息权限保持相同，资本再分配的策略键同步重命名。不能新增资金、股份或给新策略增加预测权限。每个世界核对初始资产、新闻与终局抽签一致，原有命名强 bot 全部保留。

## 健康诊断与评价

旧质量检查继续原样输出，不删除失败项。新增诊断按当前生效普通分红分为高于初始 25%、低正分红、零分红；分别统计买盘、卖盘、双边覆盖、薄侧股数及金额深度、成交连续性和点差。缺少某一状态的运行不填零，比较时报告样本数。

固定组合价值依库存配对而变，当前普通股息延伸也不等于真估值，因此旧价格偏离仅作参考；不把未知未来真实路径或配对收益当成统一的当前单股“正确价格”。同时报告现金分红、组合、现金闲置费、股票闲置费、交易费、利息和终局。股票闲置费已通过烧股影响库存/终局，市场现金恒等式不得再重复扣除。

开发准入：所有审计通过、零 bot 错误/禁用/跳过；新增账户零借款利息、零强平、零负现金；每个替换的新群体平均净收益非负；全市场平均净收益不低于同批对照；正常分红双边覆盖 >=95% 且不比对照低 1pp 以上；全状态卖盘覆盖提高至少 1pp；低分红与停息合并时段卖盘覆盖提高至少 5pp；薄侧股数深度 >= 对照 90%；Grid 毛亏损份额 <=25% 且相对对照增加 <=5pp；Tide 的全市场持股数量占比不增加。候选以低分红/停息卖盘覆盖改善最大为先，再以全市场收益为先。不得用新策略强制亏损换报价。

独立验证沿用上述条件。只有世界校准、开发准入和独立验证全部通过才考虑切换默认；否则交付实验实现与明确失败结论。股数深度和金额深度同时报告，避免把单纯股价下降误称为库存减少。所有条件在运行前冻结，留出不用于调参。

## 运行和证据

release、4 个市场线程、Windows 10 核共同亲和性预算，所有比赛通过 arena_gate 串行，方案顺序轮换，每世界重复两次。记录场景/源代码/二进制哈希、种子、重复、模拟及 CLI 墙钟。只增加开局预生成与分析；不把降低旧 bot 决策频率当作性能优化。

v20 源码、配置和 release 可执行文件已在 `runs/dividend-v20-source/` 保存。v21 分阶段保存冻结文件和原始输出，旧报告不覆盖。实施代码审查重点是可用信息、全账户现金与库存预算、挂撤单预约、负组合风险、动作上限和极端价格/零分红行为。
