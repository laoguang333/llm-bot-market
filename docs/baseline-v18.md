# v18：保留简单网格，分散初始资本与亏损

默认 `scenarios/baseline.toml` 与 `scenarios/baseline-v18.toml` 完全相同。

## 改动

保留 v17 的 105–229 个账户、19 种策略及全部策略参数。Grid 仍有 24–40 个账户，逻辑不变；每个实际开局由现金 40,000 元、每只股票 120 股调整为现金 20,000 元、每只股票 20 股。

多出的现金与每只股票按 Coral、Value、Hunter、Momentum、Shark 各 20% 分配，再在接收策略的匿名账户之间等分。各接收账户的额外份额随实际人数变化。每个世界的总现金、每只股票总量及初始总权益与原样 v17 相同。命名账户（含挑战者、Almanac、Osprey、Lattice、Titan、Horizon 等）不参与。

新增可选配置 `capital_redistribution`，仅在开局执行。撮合、费用、消息权限和决策频率不变，未阅读或修改旧 bot 策略源码。原始配置中的 Grid 大账户数值是转出前预算；实际资产以 Start 和报告的 initial 字段为准。[实现与配置说明](capital-redistribution.md)。

## 开发与冻结

[事前协议](capital-v18-protocol.md)固定两种方案和选择规则。开发使用 83001–83010，每世界每方案两次；v17、五类均分、偏重报价共 60 局。两候选均通过集中度和质量保护，两者质量均通过 14/20，v17 为 9/20。均分方案每局最大单策略亏损占比平均 20.25%，偏重报价为 24.00%，因此按预先规则选择均分。没有根据留出结果调权重。

开发期均分方案全市场净收益为 −7.58%，v17 为 −0.60%；本轮不是全市场收益最优化。原始记录见[开发结果](capital-v18-dev-results.json)。

## 审计、性能与复现

开发和留出共 140 局、2800 次守恒审计，零 bot 错误、零禁用、零跳过。逐对核对原账户身份、消息权限及实际新闻投递计数、全场初始现金/每股总量/总权益、新闻文件哈希、最终股息与终值支付；逐策略核对池的分配金额与整数余数。

全部使用 release、4 市场线程、Windows 20 逻辑核心中的 10 核共同亲和性预算，串行运行，每世界两次，轮换运行顺序，没有竞争 CPU 的基准并跑。墙钟见表，资本导致交易路径变化，不能把耗时差当成引擎性能优化。重分配只增加一次开局处理，不降低任何 bot 决策频率。

Workspace 180 项测试通过；新增测试覆盖初始资产守恒、真实收益分母、命名挑战者隔离、逐股覆盖、整数余数、无效参数和账户上限。既有撮合优先级、消息与结算测试保持通过。Market 范围的 Clippy 检查通过（仅豁免已有 `items_after_test_module`），新文件格式与 Python 语法检查通过。实验使用的二进制、引擎源码快照和哈希保存在 `runs/capital-v18-reviewed-source`；实验后引擎只经 rustfmt 换行，已核对去除空白后完全一致，最终源码重新通过测试并重建 release。

[留出完整结果](capital-v18-holdout-results.json)保存所有逐局指标、哈希、命令与耗时。正式实验源目录为 `runs/capital-v18-dev` 和 `runs/capital-v18-holdout`；输出目录或开发阶段的冻结选择文件已经存在时，脚本拒绝覆盖，重跑前应另行保存原记录。

python tools/arena_gate.py --cwd . -- python tools/validate_v18.py dev
