# v6：0.6% 闲置费与逐 tick 组合现金流

2026-10-19 按用户选定方案完成 v6 现金流改造。本报告数据生成时背景仍为旧 `news`；其改造后配置现归档为 `baseline-v6-legacy-news.toml`，改造前配置为 `baseline-v6-periodic-combos.toml`。三份默认场景仍相同，但后来已进一步采用 NewsV2，见[当前 v6](baseline-v6-current.md)；本报告不是 NewsV2 阵容的实测。参数直接采用用户选择，没有根据收益挑参数。

## 生效规则

- 闲置费仍每 50 ticks 结算，费率从平均权益的 **0.2% 改为 0.6%**。符合条件成交额的 1% 抵扣保持不变，maker/taker 都可抵扣；不是只对现金收费。
- 要完全抵扣，一期累计合格成交额须达到平均权益的 **60%**。买卖均计入，若金额相等，可理解为买入约 30%、卖出约 30%。纯现金、无交易无收入账户，一局约扣 59 次，余额约减少 `1−0.994^59 = 29.89%`，实际还受分取整影响。
- 组合在个人 tick 1–2999 逐 tick 结算。每条规则先算完整套数，再乘该规则费率，最后四舍五入到分；正负对称，半分远离零。不累计余数，不设置最低派发额。
- `combo_scale=50` 表示组合费率整数单位为 1/50 分，与普通股息的 `dividend_scale` 独立。旧配置省略时默认为 1，旧 JSON 规则同样兼容。
- 期末兑现的一单位仍代表 50 ticks。组合终值先汇总 `套数 × 每 tick 费率 × 50 × N`，最后取整，不把局内每 tick 的取整结果重复 N×50 次。因此一套在局内可能每次得到零，但期末仍有组合兑现；这保持了原有终值尺度。

| 组合 | 每套每 tick 的取整前金额 |
|---|---:|
| T1 + T2 | +0.4 分 |
| C1 + C3 | +0.4 分 |
| T3 + E2 | +0.5 分 |
| E1 + C2 | +0.3 分 |
| T4 + E3 | −0.4 分 |

例如 T1+T2 一套每 tick 发 0 分，两套发 1 分，十套发 4 分。负组合一套扣 0 分、两套扣 1 分、十套扣 4 分。T3+E2 一套的半分会取整为 1 分，因此小仓位也可能被向上舍入；这与用户接受的小仓位取整误差属于同一规则。

这是近似保持派发强度，并非逐账户等额替换。旧 3000 tick 比赛发 59 次，新规则发 2999 次，相当于 59.98 个旧周期；新闻、交易、整数套数和舍入又会改变实收金额。负组合也使用当前已入账持仓，不引入全市场同步登记。普通股息、新闻公开与生效的两个时间点不变。

估值型策略统一通过 `combo_cents` 转换单位后估计组合现金流，防止错误放大 50 倍。其按每套价值估算仍是连续近似，没有为了本次改造增加针对整数仓位舍入的优化。Swift 策略代码与参数均未改动；账户现金和市场交易路径会受到新费用影响。

## 验证与性能

94 项 Rust 测试、严格 Clippy、25 项 Python 测试、前端 JS 语法检查通过。新增覆盖正负组合、半分舍入、小仓位为零、规则有效窗口、期末尺度、旧 JSON、0.6% 费用及 60% 成交抵扣。既有撮合优先级、消息与现金/股份守恒测试通过。复盘额外核对组合现金流，防止负组合被漏算。

旧引擎和新引擎使用同一份旧配置，种子 7、11、19，1 线程：三局逐笔成交文件、全部账户现金/持股/终值/收益完全一致。

性能使用 release、3000 ticks、4 工作线程，Windows 共用 10 核预算，种子 7、11、19，各重复 3 次，另各预热一次；三种条件交替顺序，比赛串行。计时包含报告输出，录制关闭。

| 条件 | 进程墙钟中位数 | 引擎中位数 |
|---|---:|---:|
| 旧引擎、旧规则 | 1.366 秒 | 1.267 秒 |
| 新引擎、旧规则 | 1.368 秒 | 1.255 秒 |
| 新引擎、新规则 | 1.367 秒 | 1.250 秒 |

新旧整体墙钟相差约 +0.05%，没有观察到明显性能回退；不把多线程波动解释为加速收益。没有降低策略决策频率，也没有添加全市场结算屏障。

## 12 个新世界、四组对照

种子 25201–25212，每种配置每种子一次，release、4 线程、3000 ticks，共 48 局。四组为旧规则、仅提高闲置费、仅逐 tick 组合、两项都改。每个种子的新闻文件、股息路径和隐藏终值一致；多线程撮合路径允许不同。全 48 局均完成 6 次审计，零跳过、零 bot 错误、零禁用。

| 指标 | 旧规则 | 仅闲置费 | 仅组合逐 tick | 两项都改（旧 News） |
|---|---:|---:|---:|---:|
| 市场质量通过 | 8/12 | 7/12 | 8/12 | 8/12 |
| 各局价差中位数的中位数 | 0.0886% | 0.0928% | 0.0891% | 0.0913% |
| 两侧 2% 深度较小值，典型金额 | 29,299 元 | 28,463 元 | 28,703 元 | 29,417 元 |
| 双边报价样本占比，逐局平均 | 99.30% | 99.23% | 99.22% | 99.28% |
| 100 tick 内翻倍的股票×局数 | 7/120 | 7/120 | 6/120 | 6/120 |
| 全市场平均组合净派发 | 124,616 元 | 115,869 元 | 128,790 元 | 119,393 元 |
| 全市场平均实收闲置费 | 460,722 元 | 1,977,337 元 | 461,891 元 | 1,972,576 元 |
| 标准 Swift 平均收益 | +196.21% | +166.54% | +206.89% | +171.26% |
| 单次入场 Swift 平均收益 | +118.03% | +89.61% | +114.24% | +90.95% |
| hold 策略平均收益 | +5.10% | −16.56% | +4.90% | −16.56% |

市场没有出现明显的价差扩大、盘口枯竭或新增账务异常。所有质量失败均来自 `value_crossings`，即价格穿越参考估值的次数不足；旧规则也存在，不能把 8/12 写成全部质量通过。更高费用明显压低了低换手账户的收益，而逐 tick 组合对总体行情的影响较小。这批 single 的组合收入仍约 11.69 元/局，原来约 11.71 元；小仓位舍入到零不会让它的所有组合收入必然归零。

两项都改组的两个 Swift 在这 12 个种子中都盈利，但这是市场机制对照，不是挑战者打穿验收。也不能把单次入场 +90.95% 与标准 +171.26% 的差完全归因于资金，因为仓位模式和信号参数也不同。扩大费用不保证每个世界、每个仓位都比普通股息高；这里实测 hold 均值已转负。
