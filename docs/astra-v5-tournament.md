# 三名 Astra 独立开发与 v5 比赛

基础版本为 `17a705b`。三个 Astra medium 代理从同一提交分别在独立 worktree 开发 `astra_a`、`astra_b`、`astra_c`。它们从任务开始即知道另外两名独立对手存在，冻结后将三方同场比赛。开发期间互不查看对手源码，不协调交易。

## 结果（2026-10-18）

**本轮同场冠军 B，第二 C，第三 A。** B 在预定正式留出集上达到单账户打穿门槛，但额外留出集上三者都失败，不能称为稳定打穿 v5。未根据正式结果继续调整任何参赛者。

全部 **240 局、1,440 次守恒审计完成**；全体账户零跳过决策、零 bot 错误、零停用。三名参赛者在单独挑战及同场比赛中均零强平。同场平均决策耗时 A 9.84µs、B 9.11µs、C 9.84µs。市场质量是单独指标：同场赛全项通过率 **75.83%**，12 局未通过 `median_abs_log_dev`，17 局未通过 `value_crossings`；因此未达到市场质量 80% 目标，不能把守恒与策略成绩当作市场质量全部达标。

精确逐局分数、两两结果、质量指标、源码/二进制哈希见 [astra-v5-results.json](astra-v5-results.json)。原始报告、命令、六份同场场景与日志在 `runs/astra-v5-tournament-20261018`。整合版本 `6f92e43` 通过格式检查、Clippy 严格检查、全部 **31 项测试**和 release 构建；比赛前后输入哈希一致。比赛脚本另通过真实市场小规模全流程、续跑及精确收益并列排名检查。

## 预先确定的赛制

- 开发种子仅 1–20。代理可以新增自己的策略和测试，不得改变 v5、引擎、既有对手或评分标准；不得访问隐藏世界或用种子反推未来。
- 代码与默认参数冻结、整合并检查后，由主持人运行正式测试。正式测试后不按结果调参。
- 单账户挑战：每个 bot 分别加入原始 v5，正式种子 1001–1020；额外验证使用 2001–2020。两批分别报告。打穿标准保持平均百分位 ≥ 90、前 25% 占比 ≥ 80%。
- 三方同场：v5 原有人群加三个独立账户，种子 3001–3020，每个种子遍历三个账户的全部六种顺序，共 120 局。每名参赛者初始现金 20,000 元、每股 20 股。六种顺序平衡位置与私有信息分配；同一世界的六局相关，独立世界种子数仍是 20。
- 同场冠军按三名参赛者内部平均名次升序确定，平局按平均最终权益/初始权益降序。收益相同时并列名次取平均。另报告独占第一次数、两两胜负、全市场百分位、收益、强平、跳过与错误，不将同场成绩冒充单账户打穿结果。
- 保持 v5 的 4 线程和调度宽容度。跨 worktree 的市场实验通过 `tools/arena_gate.py` 串行运行，正式验收等待全部开发停止。

## 复现

```sh
cargo build --release
python tools/arena_gate.py --cwd . -- python tools/astra_tournament.py --out runs/astra-v5-tournament
```

跨 worktree 使用门闩时，必须传同一个 `arena_gate.py` 的绝对路径。所有正式批次、日志、场景、命令、源码与二进制 SHA-256 和汇总保存在输出目录。已有完整批次可以续跑；输入改变会拒绝复用，未完成批次需要保留并另选输出目录。

## 正式验收前的账务修复

B 的训练第 9 批在种子 11 因对手 `value#3: negative shares` 中止，未计入任何完整成绩。主持人检查发现闲置费扣股竞态：卖单已成交、卖方还未读取成交邮件时，撤单只能释放剩余挂单，旧代码却仍扣除预定的全部股份，侵占了已卖出待结算的股份。

正式比赛前修复为只扣实际可用股数，未扣的小数累计量留到股份可用时；新增确定性测试覆盖全部成交待结算、部分成交后撤余单两个情况，并检查结算前后守恒。测试在旧代码上失败，修复后通过。三名参赛者的策略与参数继续冻结，统一使用这一修复后的引擎，v5 场景、调度和评分门槛不变。此前代理训练成绩来自旧引擎，只用于开发记录；正式胜负按统一修复版本重新运行。
