# v6 正式验收方案（2026-10-19）

在读取本轮比赛收益前固定。使用当前工作区的引擎与 bot，包括用户在别处完成、尚未提交的修正；保存源码快照、差异和哈希。旧猎手实验维持中止，不恢复。

1. 五个 Swift 参数档沿用已准备的 v6 配置，不按本轮分数优化。Swift 源码、原有 v5 对手与所有市场规则保持现状。
2. 审查本轮实际运行的全部策略及共用代码，禁止利用 Start.seed 重建隐藏世界；允许它用于自有随机行为与参数分散。审查记录保存于 baseline-v6-bot-review.md。
3. 用 release 二进制依次运行四组：v5 背景、v6 背景、v5 + 默认 Swift 挑战者、v6 + 默认 Swift 挑战者。每组种子 20001–20020，共 80 局，每配置/种子运行一次，不按结果重复择优。
4. 所有组均 3000 tick、4 工作线程，与两个版本的场景配置一致。本机 20 个逻辑核心，Windows 总预算 10；串行运行，并通过进程亲和性让构建、LLVM、链接器、测试和比赛子进程共享该预算。测试单用例执行，避免多线程测试重叠；使用 arena_gate 与其他批量比赛互斥。
5. 使用同一源码和二进制的 v5 对照，区分新增 Swift 的影响与近期引擎修正。多线程不保证逐笔一致，报告墙钟但不将单次样本包装为性能优化结论。
6. 核对所有账户每局 3000 次决策、零跳过/错误/停用和 6 次守恒审计；验证 v6 五个 Swift 的 owner、初始资金、持股、参数身份。记录全部拒单、强平、费用及期末递延闲置费，不筛掉亏损世界。
7. 分别报告五个 Swift 账户的排名、收益、亏损局数和成交量。默认 Swift 挑战者沿用原验收线：平均排名百分位至少 90，至少 80% 的局进入前 25%。挑战者没打穿不会阻止基准升级。
8. 市场质量按现有九项阈值全部报告，并与同引擎 v5 对照；不放宽阈值来通过验收。账务/执行失败必须解决；市场质量通过率不要求 100%，但明显退化需要说明，不能宣称所有市场健康。
9. 功能测试与运行核验完成后，将 baseline.toml 指向 v6 的相同内容，保留 baseline-v5.toml。历史 v5 研究脚本和专用测试显式绑定归档 v5，通用挑战/性能工具跟随默认版本。

本轮不修改观察频率、允许时间差、撮合、结算或策略行为；当前用户已有改动仍会影响收益，报告中单独说明。这是固定配置验收，不是继续研发狩猎策略。
