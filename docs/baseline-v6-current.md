# 当前 v6：扩容背景、两个 Swift、NewsV2、逐 tick 股息

**当前现金流规则（2026-10-19）：** 闲置费改为每 50 ticks 平均权益的 0.6%；普通股息及组合收益都逐 tick 派发，按单股持仓/单条组合的完整套数合计后四舍五入。负组合同样逐 tick 扣款。组合单位为 1/50 分，终值的一单位仍代表 50 ticks。[改造报告](per-tick-combos.md)包含 48 局四组对照与性能验证；此前扩容但组合每 50 ticks、闲置费 0.2% 的版本归档为 `baseline-v6-periodic-combos.toml`。

**阵容与当前要求：** 按用户决定，原有 6–16 个旧 `news` 背景账户全部替换为 `news_v2`，保留人数范围、每账户现金 20,000 元和每股初始 20 股；采用 NewsV2 既有默认参数，没有按替换后的收益调参。版本继续叫 v6，成立时不以新 bot 打穿为前提。随后按用户新要求研发了 [Titan 十倍资金挑战者](titan-v6.md)：普通权限未通过，增加提前消息概率后通过正式 20 局及额外 40 局；它仅作为额外挑战账户，不进入背景阵容。三个 Astra 策略和 Falcon 猎手继续不加入，研究方法、结果和局限见 [Swift 档案](swift-research.md)；现有 `hunter` 是另一项背景策略。旧 `news` 与 `news_fixed` 的实现保留，历史场景不变。

| 订单流相关成员 | 账户数量 | 初始现金 / 每股库存 | 主要差别 |
|---|---:|---|---|
| `swift-standard` | 1 | 20,000 元 / 20 股 | 原版公共成交、盘口、动量信号，可加减仓 |
| `swift-early-single` | 1 | 2,000 元 / 2 股 | 较早进退，同一股票首次买入成交后不补仓 |
| `news_v2` | 6–16 | 每账户 20,000 元 / 20 股 | Swift 信号与最优价 IOC 执行，加本人已收到的新闻方向、可信度及公开后衰减 |

NewsV2 默认 `news_weight=0.35`，其余默认信号和仓位参数与标准 Swift 相同；它可以加减仓，没有 single 的持仓锁定。各账户参数相同，但私人新闻区间、实际观察和成交路径可能不同。这不是新增三个独立的策略家族：NewsV2 与 Swift 共享核心思想，因此同类机会竞争也会更强。其余 grid、value、momentum、noise、hold、hunter、shark、tracker、coral 继续在背景中运行，市场仍是 11 种注册策略。

当前基准有 **98–222 个账户、11 种策略、10 只股票**，人数由种子确定；seed 7 有 **146 个账户**，扩容前为 54 个。仍只保留两个 Swift：`swift-standard` 与 `swift-early-single`。标准版沿用原来的加减仓逻辑；较早进退版 `single_entry = 1.0`，同一股票买入成交后不再补仓，退出触发后持续清仓，空仓后才能开始下一轮。普通股息使用逐 tick 整仓舍入。

单次入场版的现金从 20,000 元减为 **2,000 元**，每只股票的初始库存从 20 股减为 **2 股**，因此总初始权益也缩为十分之一；seed 7 从 37,842 元降为 3,784.20 元。标准版资金不变。两者信号参数、IOC 最优价限制和退出逻辑均不因本次扩容而修改。

背景人数相对扩容前：grid、value、coral 的最少/最多人数乘 4，noise 乘 3，其余背景策略乘 2。增加账户也增加全市场现金和股票，并改变私有消息接收者、撮合与调度路径，不是只改变人数而固定所有其他条件。完整阵容、60 局对照、性能和翻倍行情分析见 [扩容报告](v6-population.md)。

单次入场按每只股票独立执行，不是整个账户只能持有一只股票。零成交的 IOC 可以重试；部分买入哪怕只有一股，也视为本轮已入场。持仓期间不随权益变化小幅加减仓，卖出仍只打最优买价，流动性不足时可能分多次退出。初始库存也先清仓再进入新一轮。不降低决策频率，不改变撮合或结算。

`baseline.toml`、`baseline-v6.toml`、`baseline-per-tick.toml` 现在相同。NewsV2 替换之前、已采用 0.6% 费用与逐 tick 组合的版本保存在 `baseline-v6-legacy-news.toml`。扩容前、单次入场版尚未缩减资金的 35–80 人配置保存为 `baseline-v6-pre-expansion.toml`。原来的周期派息五 Swift 配置保存为 `baseline-v6-five-swift.toml`，逐 tick 五 Swift 配置保存为 `baseline-per-tick-five-swift.toml`。历史源码/计划 JSON 仍保留其生成时的路径和哈希；复现时使用冻结快照，或明确选择对应归档配置。

## NewsV2 替换验证（2026-10-19）

运行前重新阅读 `news_v2.rs` 与其新闻事件 helper：策略只用本人已收到的新闻区间、公共盘口/成交和自己的账户，不重建世界种子、不访问隐藏世界或其他账户。沿用既有默认代码，没有改策略、引擎或观察频率。新闻权重为零与普通 Swift 一致、新闻影响决策而种子不影响决策的 2 项测试通过；组合单位及终值的 3 项测试、Swift 诊断重建的 1 项测试通过。release 构建完成。

替换前后使用同一 release，种子 7、11、19，每种场景每种子重复 3 次，各预热一次；4 工作线程，3000 ticks，Windows 所有进程共用 10 核预算，经过基准锁串行运行。正式记录共 18 局，只有 3 个世界，不冒充 18 个独立世界。外生新闻、股息路径和终值指纹一致，多线程成交路径允许不同。

| 检查 | 旧 News 阵容 | 当前 NewsV2 阵容 |
|---|---:|---:|
| 质量全项通过 | 8/9 | 9/9 |
| 进程墙钟中位数 | 1.300 秒 | 1.306 秒 |
| 引擎墙钟中位数 | 1.195 秒 | 1.196 秒 |
| 逐局典型价差的中位数 | 0.1152% | 0.1209% |
| 两侧 2% 深度较小值，典型金额 | 18,253 元 | 18,107 元 |

| 现金/股份守恒审计 | 54 次通过 | 54 次通过 |
| 跳过 / bot 错误 / 停用 | 0 / 0 / 0 | 0 / 0 / 0 |

替换后 seed 7/11/19 分别仍有 146/167/164 个账户，NewsV2 为 8/8/6 个；恰有两个 Swift，没有旧 News、Astra、Falcon 或额外挑战者。所有账户各完成 3000 次决策。旧组唯一质量失败是 `value_crossings`；这小批检查中没有看到明显性能回退或流动性恶化，不据此声称覆盖所有市场。

行为变化是原来短暂新闻跟单改成持续订单流交易并带新闻偏置，更多账户会竞争 Swift 的机会。该批普通 Swift 平均收益 +77.69% → +82.23%，single +41.28% → +68.28%；这是三个世界重复路径的描述，不能证明替换稳定改善 Swift，也不是打穿验收。没有根据这些收益调整人数或策略参数。

[验证数据](baseline-v6-news-v2-validation.json)记录源码审查、二进制/场景哈希和逐局结果，原始输出在 `runs/v6-news-v2-20261019`。已有调试器录制 `runs/swift-cashflows-seed7`（8768）生成于替换前，仍含旧 News；今后默认录制使用新阵容，旧录制保留原貌。

## 历史验证

此前扩容验收使用种子 25101–25112，release、4 线程、每配置每种子一次，串行运行，当时仍为 0.2% 闲置费与每 50 ticks 组合收益。扩容方案质量通过 11/12，零跳过、零 bot 错误、零禁用，既有现金/股份审计通过。进程墙钟中位数由 0.450 秒增至 1.260 秒；100 tick 内翻倍的股票×局数由 10/120 降至 5/120，不能消除新闻与低价反弹引起的大涨。此处是历史市场配置验证，没有追加挑战者或执行打穿验收。

历史验证（加入单次入场模式之前）：release、4 线程、种子 24001–24020 的 20 局，均恰有两个 Swift；质量通过 13/20，全部账户零跳过、零 bot 错误，既有现金/股份审计通过。86 项 Rust 测试及严格 Clippy 通过。这些成绩不能直接归属于新配置；新模式是为了便于观察完整操作，并未证明提高收益。录制与连线说明见 [交易调查台](swift-debugger.md)。
