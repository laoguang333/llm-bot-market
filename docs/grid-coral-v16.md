# Coral 的流动性与 Grid 的损失：v16 逐笔分析

2026-10-21。针对 [生态调查](ecology-v16.md)的追问，重新读取原样 v16 的 20 个世界、每世界两次，共 40 局成交、盘口、股息和最终账本。没有重跑这些世界，没有查看旧 bot 实现，也没有修改 Grid 或 Coral。新版本 [v17](baseline-v17.md)另行追加 Almanac、Osprey v2，不混入这份历史分析。

## “流动性骨干”应如何理解

挂在订单簿上、等待别人来成交的是被动订单（maker）。有人急于卖出时，这些买单提供接手价格和数量；有人急于买入时，卖单提供货源。主动吃单者（taker）则消耗当时可见的报价。一个账户既可以挂单，也可以主动成交。

收益排名衡量账户自己赚了多少，流动性作用衡量它给其他人提供了多少可成交报价，两者不是同一指标。本轮不能仅靠总成交量证明“去掉它之后市场会怎样”；要量化这个反事实，仍需单独的人口和资金对照。

上一份报告用双边成交参与量描述 Coral 的重要性，口径过宽。逐笔拆分后的结果：

| 指标，逐世界等权 | Coral | Grid |
|---|---:|---:|
| 全市场初始权益占比 | 4.42% | 50.48% |
| 全市场双边成交参与额占比 | 24.67% | 19.69% |
| 自身成交额中被动成交比例 | 57.64% | 90.26% |
| 全市场成交额中由该组作为 maker 的比例 | 28.17% | 35.54% |
| 排除同策略互相成交后，上述 maker 比例 | **13.78%** | **32.90%** |
| 自身成交参与额中，同策略不同账户互相成交比例 | 55.56% | 13.24% |
| 平均净收益 | +213.46% | −97.64% |

“全市场成交额”每笔交易只计一次；“双边参与额”分别记入买卖双方，分母为前者两倍。表中每行先逐局计算比例，再对 40 局等权平均，不能用各行平均值直接相除。排除同策略成交指不同 Coral 账户之间、或不同 Grid 账户之间的交易，不是同一个账户自成交。

更准确的评价是：**Coral 是重要的流动性参与者，同时进行主动交易和持仓收息。** 它为其他策略承接的被动成交占全市场约 13.8%，而不是把 24.7% 全部当成对外供给。Grid 目前的对外被动供给更大，所以直接删除 Grid 会同时移除大量盘口和股票供给。

Coral 也不是每一侧报价都好。下面的成交后检验显示，它的买入选择优于 Grid，卖出侧仍经常放弃后续上涨。它的收益中有很大的持仓股息贡献，不能全部解释成点差收入。

## Grid 的逆向选择是否严重

一个挂出 99 元买价、101 元卖价的交易者，并不保证均匀地买到和卖出。如果新信息使合理价格接近 90，别人倾向于把货卖给它的 99 元买单；如果合理价格升到 110，别人倾向于吃掉它 101 元的卖单。原本看似能赚 2 元的价差，会变成在不利方向被选择成交。这里只是概念例子，不是本轮某条真实成交。

本轮使用实际成交价与之后盘口中点做核对，另加入这段时间每股理论股息：

- 买入：`未来中点 + 期间股息 − 买入价`；
- 卖出：`卖出价 − 未来中点 − 期间股息`。

正值表示该次交易相对这段持有期有利，负值表示不利。每局按成交金额加权，再对世界等权平均。只看与其他策略的成交，排除同类互相成交。

| 被动成交方向 | 约 10 ticks 后 | 约 50 ticks 后 | 约 200 ticks 后 |
|---|---:|---:|---:|
| Grid 买入 | −1.07% | **−1.14%** | +0.30% |
| Grid 卖出 | −1.36% | **−2.19%** | −3.81% |
| Coral 买入 | +0.43% | **+0.77%** | +1.22% |
| Coral 卖出 | −0.85% | **−1.28%** | −2.50% |

Grid 在 10、50 ticks 的两侧成交质量都较差，卖出侧尤其明显，与严重逆向选择的解释一致。买入到 200 ticks 的含息结果转正，说明不能把所有 Grid 买入概括为“越抄越跌”；短期成交不利与较长时间的持有回报可以不同。

Coral 对外主动买入的对应数值为 +1.29%、+3.33%、+6.07%，显示它除了提供挂单，也会主动挑选有利机会。该结果是历史成交条件下的统计，没有隔离消息、行情、成交冲击等因素的因果贡献。

### 统计边界

盘口每 10 ticks 记录一次，因此实际观察延迟为目标值至目标值加 9 ticks。只使用未来同时存在买卖价的快照，不填补缺失盘口；Grid 对外被动成交在约 50 ticks 时覆盖约 99.7% 的金额。计算同时扣除了卖出后放弃的股息，避免把正常派息相关的价格变化误认作选择优势。

这不是逐笔实际已实现净利润，也不是逆向选择的纯因果估计：未扣交易费、融资和闲置费；假设成交数量持有到观察时点；股息按每股理论额计算，没有模拟整仓舍入；不同成交的观察窗口会重叠。尤其不能把这些百分比直接累加成账户 −97.64% 的损失。

## 为什么不是单纯“抄底后套牢”

Grid 开局每只股票 120 股，普通账户 20 股。按这批世界的初始价格，它开局约 **89.59% 的总权益已经是股票**。它一开始就承担很大的持仓风险，不是拿着大笔空闲现金等跌下来才入场。

全局结束时：

- 平均只剩开局 **3.48% 的股数**；
- 净卖出股数约为开局的 **94.24%**；
- 另有约 **2.28%** 的开局股数用于股份缴费；
- 但累计买入支出为初始权益的 **39.81 倍**，卖出收入为 **39.69 倍**，净交易现金流反而为 **−12.84% 初始权益**。

这四项按各世界比例平均；股数是全股票数量之和，不能当作同一种股票的配对交易分析。它们仍清楚说明：绝大多数开局股份已经被卖出或扣除，买卖合计却没留下对应现金。因此不能用“只是持着跌价股票、账面亏了”解释这批结果；反复交易和库存更替是重要部分。

文档记载的 Grid 会按估值与价格重新铺网格，并处理多余库存。重新铺网格可能使“低位卖出、锚点上移后更高价买回、再在回落中处置”形成实际损失。**这是接下来需要报价与订单生命周期归因验证的机制，本轮没有测出多少损失具体来自重铺。** 单独“卖早了”只是错过后续收益，不足以解释绝对财富大幅减少。

按每局初始总权益为 100，平均账本可精确拆为：

| 项目 | 净收益贡献 |
|---|---:|
| 交易现金流＋期末持仓兑现−开局股票价值 | −100.56 |
| 普通股息 | +13.60 |
| 组合股息 | +0.17 |
| 交易手续费 | −3.99 |
| 现金闲置费 | −6.67 |
| 融资利息 | −0.20 |
| 盘中坏账核销 | 小于 +0.01 |
| **最终净收益** | **−97.64** |

股份闲置费约为初始权益的 2.47%，已通过库存减少包含在第一项中，不能再扣一次。所有世界均独立核对成交金额、最终现金等式、股数减少与股份缴费，以及总权益变化；逐分一致。

Coral 相同口径为：交易/库存/终值合并项 +9.61，普通股息 +323.60，组合股息 +10.01，交易费 −64.71，现金闲置费 −6.74，利息 −58.31，合计净收益 +213.46。股份闲置费同样已包含在合并项。这是会计拆分，关闭股息后策略和价格路径会变，不能直接把 +323.60 当作可移除的独立因果收益。

## 建议怎么改

先修交易质量，再处理资本集中。两项应分别实验，避免把缩小账户后的改善全算作算法进步。

1. **让不再合理的旧报价及时失效。** 收到合法新消息、股息变化或显著行情变化时，检查受影响股票两侧订单，优先撤掉过时价格。私人信息领先造成的选择风险无法完全消除，需要报价保护，而不是读取未来信息。
2. **网格宽度覆盖实际风险和成本。** 不只按固定价格间距铺单；结合波动、点差、费用及近期已实现的成交后表现，扩大风险较高一侧的价差、减少深度。新反馈只能使用已经成熟的历史观察。
3. **限制库存与重铺后的换仓。** 持仓越多，新增买单越小；设置单股和全账户暴露预算，避免网格重设自动产生大规模“卖低买高”。保留适量深度，不能靠不交易掩盖问题。
4. **把剩余派息和终值纳入风险预算。** 临近结束时检验库存兑现能否覆盖债务；剩余时间缩短后，早期合理的网格锚可能已经过高。退出仍按实际流动性执行。
5. **单独检验资本配置。** 当前由一个明显失血群体持有约一半开局资本，生态容易过度依赖它。可以把 Grid 库存逐步降到普通账户同量级，或让多种经过验证的报价策略分担资金；同时测量盘口深度与成交连续性，不能直接删掉最大的外部被动供给。

先做固定资本的原版/报价更新/库存控制/两者组合四组，再单独做资本配置对照。验收应同时看收益、买卖两侧含息成交后表现、回撤与强平、对外被动深度、拒单、市场质量及守恒。v17 本次只加入两名已授权的新成员，Grid 改造尚未实施。

## 证据与复现

[机器可读结果](grid-coral-v16-results.json)保存每局方向、主动/被动、同类/其他策略、观察覆盖、阶段成交与账本拆分。源头为冻结的 `runs/ecology-v16/baseline-*`，包含原始成交、盘口、股息、账户数据；分析不读取 bot 源码。

```sh
python tools/arena_gate.py --cwd . -- python tools/analyze_grid_coral.py
```

Windows 共用 10 核预算，串行读取 40 局。每局分析缓存记录四个输入文件的 SHA-256；输入变化会重算。没有符合某类成交的世界不被填成零收益，结果保留实际有成交和有观察覆盖的运行数。最初汇总遇到空成交分组后修正，完整重算成功；没有删掉失败世界或选择较好的重复运行。
