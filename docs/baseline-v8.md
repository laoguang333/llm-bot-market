# v8：1 万 ticks 长局与性能实测

本文是 v8 发布时的历史记录；当前默认已升级为 [v9](baseline-v9.md)。`baseline-v8.toml` 和下述原始数据保留，本文的“当前”均指当时版本。

当前默认 `scenarios/baseline.toml` 与 `baseline-v8.toml` 相同：**10000 ticks，单股平均约 100 ticks 涉及一次消息**。沿用 v7 的全部已审查策略、资金与人数配置，99–223 个账户；没有修改 bot 实现或降低其决策频率。3000 ticks 的 `baseline-v7.toml` 与历史结果保留。

用户先提出 5000 ticks、平均 50 ticks 一次消息，再确认：若 1 万 ticks 的耗时可以接受，则采用 1 万 ticks、平均 100 ticks 一次消息，让相近数量的消息之间有更多交易时间。实测完整普通比赛约 4.5 秒，20 局约 88.5 秒，因此选择长局作为当前默认。

## 实际改动

| 参数 | v7 | 当前 v8 |
|---|---:|---:|
| 比赛长度 | 3000 ticks | 10000 ticks |
| 附加经营更新机会：每股、每 1000 ticks、平静期 | 20 | 5 |
| 同上，动荡期 | 60 | 15 |
| 终值私人提示时点 | 0 / 1000 / 2000 | 0 / 3333 / 6666 |
| 大龙身份相关增长偏置开始分化 | 1650 | 5500 |
| 局部经营阶段持续长度 | 约 105–300 ticks | 约 350–1000 ticks |

后两项由原有机制按游戏长度缩放。普通市场/行业/个股新闻生成率及幅度没有改变；只减少附加小幅经营更新的频率。机会取整后无变化则不发消息，因此配置中的 5/1000 不能直接换算为最终消息间隔。

消息统计按某只股票实际涉及的独立事件计数，包含市场、行业和个股事件；同一事件的私人披露、公开、生效不重复计数。20 个另外选定的种子中，每股平均涉及 101.72 条新闻，对应 **98.31 ticks/条**。每局先对十股汇总，其平均间隔在 85.5–108.8 ticks 之间；这不代表每一只股票的每次等待都在此区间，也不设固定新闻日历。

现有消息仍最早提前 120 ticks，首次私人披露后 60 ticks 全面公开，再过 60 ticks 生效。Titan 新闻倍率仍为 1。**数百/上千 ticks 的远期消息权限、十倍大龙目标、相应的新质量检查还未在本次加入。** 本次落实的是时长与消息密度选择。

## 性能实验

Windows，20 个逻辑核心；通过进程亲和性将模拟及子进程限制在同一份 **10 核预算**内，市场工作线程为 **4**。这表示遵守半机 CPU 上限，不是人为把 CPU 主频降低一半，也没有占满 10 个市场线程。

使用 release 构建、经 `arena_gate.py` 串行运行，没有同时跑竞争 CPU 的构建或实验。计时种子为 7、11、27003、27006，覆盖有/无指定大龙，账户数为 147、168、166、179；每种配置每种子重复 3 次，各配置先预热，执行顺序交替。下表每行 12 次计时，重复不算新世界。

| 场景 | 进程墙钟中位数 | 墙钟范围 | 引擎内中位数 | 实测单股消息平均间隔 |
|---|---:|---:|---:|---:|
| 原 v7：3000 ticks | 1.426 秒 | 1.373–1.577 秒 | 1.285 秒 | 59.58 ticks |
| 候选：5000 ticks | 2.398 秒 | 2.240–2.868 秒 | 2.186 秒 | 54.27 ticks |
| 采用：10000 ticks | 4.499 秒 | 4.244–5.167 秒 | 4.059 秒 | 100.18 ticks |

1 万 ticks 的完整墙钟约为 5000 ticks 的 1.88 倍，原 3000 ticks 的 3.16 倍。5000 与 10000 配置每股平均事件数分别约 92.13 与 99.83，达到了消息总量相近、交易时间更充裕的意图。少量时间样本不能证明复杂度严格线性。

进程墙钟包含启动、世界生成、交易、分析和普通 CSV/HTML 报告写出；**不包含逐账户逐 tick 调试录制及浏览器渲染**。完整调试模式的耗时与磁盘量需要另测。普通输出在 20 局长局中平均约 34 MiB/局。

## 20 局连续运行

另用种子 28001–28020，当前长局每种子一次、仍为 4 线程串行。账户数 134–185。这批用于检查运行、消息密度及发现行为异常，不是挑战者打穿验收，也不是固定行情上的策略收益比较。

- 整批墙钟 **88.52 秒**，单局中位数 **4.516 秒**，范围 **3.730–5.217 秒**。
- **零跳过决策、零 bot 错误、零停用**。
- **400 次现金/股份审计通过**；当前默认配置下的 **104 项 Rust 测试通过**。
- 原有五项流动性检查全过 18/20，原有九项检查全过 18/20。旧估值/穿越检查仍是诊断指标，不等于资金安全或策略有效性。

本轮总计 6 局初测、3 局预热、36 局计时、20 局连续验证，共 65 局。所有运行的原始结果保留；收益未用于选择消息频率或策略参数。

## 长局暴露的行为变化

**性能足够，但融资尾部风险尚未解决。** 20 局中 14 局发生强平，合计 171 次；10 局产生坏账，合计 **646081.32 元**。其中 seed 28012 一局为 **522264.61 元**。原始账户记录可以区分不同策略及同账户的多次强平。

在另外的重复计时组中，seed 27006 的两个长局重跑分别产生 **8374402.73 元**与 **2046440.15 元**坏账，而另一次没有坏账。多线程交易允许不同路径，这里已出现很大的尾部差异，不能用中位耗时或账务守恒通过来掩盖。坏账按既有规则核销，审计通过不代表这类损失经济上合理；后续需要单独调查融资、强平执行和极端成交路径。

收费并未降低：仍每 50 ticks 按平均权益的 0.6% 收闲置费，成交抵扣仍为 1%。理想化的纯现金、不交易账户，3000 ticks 经 59 次收费约损失 29.9%；10000 ticks 经 199 次约损失 69.8%。这会压缩长期等待策略的容错，弱策略可能在长局中接近耗尽权益。

开价公式计入剩余派息，因此同样初始股息下，T1 中心开价从约 89.98 元变为 229.98 元。初始现金/股数未缩放，各账户的现金占比和下单容量也随之变化。普通新闻经过更多轮抽样，股息与价格的路径风险同样增加。这不是把原来的行情视频简单拉长；当前速度结论不能代替长期经济平衡验证。
