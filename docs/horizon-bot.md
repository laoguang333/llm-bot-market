# Horizon：远期现金流研究策略

当前 `horizon` 为 v3：把普通交易与持续跟踪的远期研究计划分开，收到远期消息就参与路径判断；不针对大龙设规则。资金与 Titan 相同，正常承担所有费用。完整设计、固定参数对照与边界见 [v3 研究](horizon-v3.md)。

v3 会联合考虑“近期利空、远期恢复”，为后续建仓预留额度；价格先跌下来也可以提前进入后续阶段。消息公开不是清仓信号，后续坏消息推翻判断才取消研究计划；普通交易核心仍可独立持仓。宽区间缩小研究仓位，实际借款增加等待成本，临近结束还检查保守兑现资产能否覆盖债务。这些行为不保证每次抄底或长期判断都正确。

固定 40 新世界中，v3/1000 平均 +583.42%、中位数 +413.32%，38/40 胜过旧 v2/1000，40/40 胜过不使用额外研究的对照；33/40 胜过同场 Titan。v3/300 中位数更高，1000 档并未稳定优于 300 档。取消分批的 20 世界组平均收益更高但出现亏损局；完整数字、现金流拆分和成交连续性恶化见 [v3 报告](horizon-v3.md)。

当前 [v12 基准](baseline-v12.md) 已将 `horizon` v3/1000 正式放入背景，接替旧 Horizon 的位置，账户名仍为 `horizon-incumbent`。上轮研究以固定 [v11 基准](baseline-v11.md) 的 `horizon_v2`/300 为对手，再追加一个新策略账户；该阵容和数据保留。当前名称对应关系：`horizon`＝v3、`horizon_v2`＝原样保留的 v2、`horizon_v1`＝原始版本。v9/v10 冻结程序中的 `horizon` 仍指当时版本。

**v2 历史结果：** 旧 v10 的 40 世界中，300-tick 组平均 +462.68%、中位数 +356.99%，39/40 进入前 25%；1000 组由 v1 的 +66.95% 提高到 +219.28%。300 组只有 18/40 局胜过同场普通 Titan；远期权限仍未充分利用。完整记录见 [v10 报告](baseline-v10.md)。[`scenarios/horizon-v10.toml`](../scenarios/horizon-v10.toml) 现显式调用 `horizon_v2`，避免名称升级改变历史策略。

**以下内容是 v1 历史记录。** 当前程序使用 `horizon_v1` 可调用其原始代码；v9 冻结程序的名称仍是 `horizon`。

这是本游戏内的新实验策略，不是现实市场交易建议。它与 Titan、Swift 各自独立，注册名 `horizon`。同一份策略代码以普通权限、300/600/1000 ticks 远期权限运行；没有为不同权限另外调参。

## 信息与交易规则

- 只读公开 Rules 和账户收到的 Observation。代码不读取 `Start.seed`、账户身份、未来世界、文件或网络，不推断隐藏大龙身份。运行前已检查这些信息边界，并测试相同观察、不同种子和权限仍产生相同动作。
- 按新闻 ID 保存所有已收到区间的交集，按实际生效时间排序。将当前股息、近期负变动、较远的正变动分段积分到期末；每段股息最低为零。已生效消息删除，避免重复计入。
- 使用区间中点减去区间宽度的 20% 作为保守估计；这并非完整概率模型。期末倍数使用本人提示与公开范围的交集中点。
- 用当前股息估值与实际价格的比例做 1500 ticks 的缓慢校准。新收到的未来变化不会立即被校准抵消。最后 1000 ticks 逐步回归现金流价值。
- 显式扣除消息等待期间的闲置费、可能的融资利息和双边交易费估计；不假定未来一定有足够换手来抵扣闲置费。默认杠杆上限 1.2、单股权益占比上限 35%、每次下单切片为权益的 2%。
- 若未来 400 ticks 内有已知负变化，先只允许建原目标的 30%。观察利空生效后，再按剩余消息重新计算。临时利空可以被远期利好覆盖，但不是任何利空都加仓。
- 原判断失效时减少目标仓位，以距中间价约 0.3% 的小片限价 IOC 尝试退出，避免把卖单一直挂在过时估值上。订单执行复用公共 `requote`，保留合理挂单时间优先级，不使用 Swift 的订单流评分。

这种策略仍会出错：未知消息会改变未来路径；宽区间会产生估计偏差；低估值可能长期低估；长期等待在 0.6%/50 ticks 闲置费下很昂贵。多给信息并不保证提高利润，不能把单次成功当作打穿。

## 远期消息权限

在账户组上指定，缺省关闭：

```toml
forecast_access = { horizon = 1000, coverage = 0.5, range_width = 3.0 }
```

三个参数分别是最大提前时间、每条合格事件的覆盖概率、区间宽度（该事件标准差的倍数）。实验保持普通消息倍率 `news_multiplier=1`，只改变额外远期权限。

每条合格消息独立抽取提前量，在 121..horizon ticks 间均匀分布；实际投递时间不得早于开局，也必须早于原来的首次披露。只提供局内会生效的消息。300/600/1000 是最大提前量，不代表每条消息都能提前那么久，更不代表能看到完整未来。

大龙模式启用时，原首次披露在 55% 分界之后的**所有消息**，包括普通市场/行业消息，额外远期投递都不早于该分界。这既保护大龙路径，也防止未来合并事件编号间接暴露身份。代价是分界附近的真实提前量更短。该规则对所有股票、所有账户一致，开局到中局仍不能确定指定者。

`NewsItem.forecast=true` 区分额外研究。`first_reveal_tick` 仍表示普通机制最早披露时间，因此可以晚于本人收到远期研究的时间；`public_tick` 和 `effective_tick` 保持原义。后续普通披露与公开照常投递，区间始终包含真实变化。额外研究的独立随机抽签不改变世界路径、其他账户消息或原有消息抽签。

## 可复现运行

```text
python tools/arena_gate.py --cwd . -- target/release/llm-market.exe challenge scenarios/baseline-v9.toml --bot horizon_v1 --cash 20000000 --shares 200 --forecast-horizon 1000 --forecast-coverage 0.5 --forecast-width 3 --seeds 40 --first-seed 29001 --threads 4 --out runs/horizon-example
```

现金为分：20000000 分 = 20 万元，各股票 200 股，均为普通账户的十倍。普通对照使用 `--forecast-horizon 0`，其余设置不变。Windows 还须将运行进程限制在半机 CPU 亲和性预算；研究脚本 `tools/research_horizon_news.py` 已处理。

实测、世界形态、融资尾部调查和性能汇总统一记录在 [v9 研究](baseline-v9.md)。新策略仅作为额外实验账户，默认基准仍保留普通权限 Titan，未给它增加远期权限或免除费用。

## 对“看得更远反而更差”的代码复查（2026-10-19）

三档研究权限整局平均都收到 379.35 条额外研究，主要区别是更早收到，而非整局消息数量更多；远期组会同时保留更多未生效的宽区间。

当时 v1 实现存在三个需要消融验证的策略缺陷，不能把表现倒退解释成信息无用：

1. 每条消息都独立扣宽度的 20%，再把这些调整累加进股息路径。这会引入随未决事件数增长的保守偏差，并非经过校准的联合风险估计。例如录制 `v9-replay` 的 E3 消息 #449，tick 5500 首次收到 −32..49，计算为 8.5 − 16.2 = −7.7；之后公开的真值是 +8。这里是策略把不确定利好当作负变化，不能说 bot 当时知道真实利空。
2. 等待折价直接包含闲置费，却没有与同时间持有现金或其他资产的净结果作一致比较。现金也承担闲置费；交易抵扣、股份扣费及融资约束应分别处理。当前折价不等于买入方案相对于现金的增量成本。
3. 任一保守估计为负的事件进入 400 ticks 窗口，就把目标仓位乘 0.30，包括已有仓位。价格是否已提前充分下跌没有单独判断，因此可能在已经便宜时仍减仓，而不是主动利用暂时利空。

这些缺陷可以从代码确认，但各自对 300/600/1000 组收益差异的贡献尚未做消融定量，v9 冻结策略和历史结果未修改；后续 v2 的改造及新结果单独记录。后续适合比较：原策略、取消逐条偏置、正确比较现金持有成本、远期信息只在临近生效时启用，并分别统计利好、暂时利空与持久利空窗口。
