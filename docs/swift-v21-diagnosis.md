# Swift 为什么在 v21 双替换环境中退化

**结论：Swift 失去了原生态中的部分短线交易优势；Coral 提供的成交对手盘没有被 Relay 接替，成交后的价格延续也变弱。standard 沿用持续调仓，进一步放大了价差损失。** 费用上涨、停息股票长期套牢、单个深度指标错误，都不能解释主要结果。

研究没有修改生产 Swift、市场规则或默认场景。复核既有 88 局，新增 8 局只读逐笔记录及 60 局参数消融。具体种子和假说见 [事前协议](swift-v21-diagnosis-protocol.md)。这里的“原阵容”和“双替换”使用相同的中等风险分红世界，区别仅为匿名 Value → Harbor、Coral → Relay；不是在比较两个不同的公司世界。

## 先纠正“原来都很强”的印象

原 v21 独立组每方案 20 局，10 个世界各重复两次：

| Swift | 原阵容平均 / 中位净收益 | 双替换平均 / 中位净收益 | 盈利局数变化 |
|---|---:|---:|---:|
| standard | +39.41% / −30.02% | −78.80% / −92.34% | 7/20 → 1/20 |
| early-single | +157.33% / +128.11% | −24.68% / −29.82% | 20/20 → 5/20 |

standard 的原均值受少数大赚世界拉动，本来就不稳定；early-single 的退化尤其明确。先合并每世界的两次重复，两个账户在 **10/10 个世界**中都因双替换而收益下降。新的 90701–90706 消融批次也重复出现这个方向：**6/6 个世界**均下降。因此不只是某一次并发撮合偶然不利。

standard 与 early-single 除执行方式外，资金、进出场阈值、杠杆和单股上限也不同，不能把两者全部差距直接归于 single_entry。后文另做只改变 standard 一个参数的实验。

## 亏在哪里：价差收益消失，费用反而少了

原独立组，以下金额均除以各账户初始权益，再跨比赛等权平均：

| 项目 | standard 原 → 新 | early-single 原 → 新 |
|---|---:|---:|
| 交易现金流＋终局−初始股票价值 | +18.26% → −88.88% | +222.62% → −29.20% |
| 普通股息收入 | +86.57% → +45.06% | +60.14% → +49.11% |
| 现金闲置费＋交易费＋利息 | 65.97% → 35.58% | 125.77% → 45.19% |
| 强平次数 | 0 → 0 | 0 → 0 |

第一行是精确账目的交易/库存/终局残差，不单独称为交易利润；股票烧毁已经影响终局和库存，不能再扣一次股票闲置费。累计费用可以超过初始本金，它不是单期费率。新环境的较低费用也部分来自资产缩水，不能当作“降低费用”的反事实实验；两环境费率本来就相同。

另取 90601–90604 四个世界各跑原阵容和双替换，逐股 FIFO 核对实际买卖、开局库存、烧股及剩余终局。16 份 Swift 记录的现金、成交笔数、手续费、分红、组合及库存残差全部精确对上。新买入股票随后已卖出的价差收益如下，不包含开局股份、股息及费用：

| 每局先按配对买入成本加权，再跨四世界等权 | 原阵容 | 双替换 |
|---|---:|---:|
| standard 已完成买卖的平均价差收益率 | −0.02% | −1.21% |
| early-single 已完成买卖的平均价差收益率 | +1.41% | −0.05% |

standard 在双替换记录中的新买入已卖出价差损失，平均达到初始权益的 **101.38%**；期间分红等收入补回一部分，所以总亏损不等于这个数。四个记录世界里两个 Swift 都在结束时清空了持仓，终局残差为零。主要是已经兑现的损失，不是报告末尾的估值跳变。

## 原来依赖谁：Coral 是重要成交对手，Relay 没有接上

原独立组实际成交账本显示：

| Swift 成交金额中 Coral 作为挂单对手的份额 | standard | early-single |
|---|---:|---:|
| 全部成交 | 58.23% | 49.82% |
| Swift 买入 | 46.84% | 36.67% |
| Swift 卖出 | **69.59%** | **62.76%** |

双替换后，Relay 在两个 Swift 全部成交中的份额仅 **0.18%、0.20%**。standard 的卖出对手转为 Tracker 52.17%、Shark 27.30%；early-single 为 Tracker 41.10%、Shark 24.77%。这是成交对手结构变化，不能直接把每个对手的成交额称为其从 Swift 赚走的钱。

原开发组四方案可进一步区分两种替换。将每种替换在“另一个群体保留/也替换”两种条件下的作用平均，按世界配对：

| 替换引起的平均净收益变化 | standard | early-single |
|---|---:|---:|
| Value → Harbor | −20.13 个百分点 | −51.11 个百分点 |
| Coral → Relay | −48.88 个百分点 | −66.35 个百分点 |

两种替换都不利，Coral 替换的平均影响更大。Value 替换对两个账户均在六个世界不利；Coral 替换对 standard 为 5/6、early-single 为 6/6。不应将整个退化只归于一个对手。

## 信号为什么不再好用

Swift 的代码只看公开成交方向、盘口深度、价格动量。分数是 `0.7 × 10-tick 成交方向 + 0.3 × 30-tick 成交方向 + 深度权重 × 深度不平衡 + 动量权重 × 价格动量`。达到固定阈值即设定目标仓位，未估计该环境下这组信号能赚多少价差，也没有把预测收益与来回成交成本比较。

四个记录世界中，固定采样、前后均有双边盘口的正信号，其未来 30 ticks 中价平均变化从 standard **+1.21% → +0.09%**、early-single **+1.05% → −0.05%**。这是事后条件统计，排除了未来缺边样本，不是可直接交易的收益。

实际买入后再看 30 ticks 的买一报价，加入期间普通股息但不含手续费、利息、组合：

| 买入金额加权报价变化，各局计算后等权 | 原阵容 | 双替换 |
|---|---:|---:|
| standard 所有买入 | −0.07% | −0.46% |
| standard 首次开仓 | +0.33% | −0.09% |
| standard 后续补仓 | −0.18% | −0.64% |
| early-single 首次开仓 | +0.33% | −0.17% |

报价可能不足以容纳整笔数量，持仓也可能早于 30 ticks 卖出，所以这只是方向/逆向选择诊断，不能当作实际持有收益。实际已完成买卖的价差账目提供了另一条独立核对：优势确实退化了。

在四个记录世界里，以有后续报价的全部买入金额为共同分母，Horizon 对手的买入对 30-tick 报价变化贡献分别为 standard −23.79 bps、early-single −37.92 bps，是主要负项之一。这提示知情卖方的成交选择值得进一步研究；当前未单独消融 Horizon 的资本或研究权限，也不能把报价变化直接当成已经转给 Horizon 的利润。

## standard 的持续调仓放大损失

standard 信号转多后保持目标权重，随后根据当前权益和价格每 tick 调整目标股数；只要没有跌破退出阈值，就可能继续买到目标仓位。退出阈值比入场阈值低，持仓具有迟滞。early-single 首次成交后不再补仓或随权益缩减，而是等退出信号；部分退出也会继续完成。

新环境记录中，standard **64.73% 的买入金额是后续补仓**，这些买入的 30-tick 报价诊断为 −0.64%，比首次开仓的 −0.09% 更差。但“全靠下跌摊平”也不准确：低于现有持仓成本的追加买入只占全部买入金额的 **11.91%**；补仓包含价格、组合权益和部分成交后的多种调整。

为排除资本和其他阈值差异，另外使用 90701–90706 六个新世界、各重复两次。只通过已有参数做干预，代码、费用和资金均保持不变：

| 新消融组，每方案 12 局 | standard 平均净收益 | early-single 平均净收益 |
|---|---:|---:|
| 原阵容 | +39.89% | +188.37% |
| 双替换 | −76.93% | +4.88% |
| 双替换，两个 Swift 的深度权重归零 | −73.05% | +9.83% |
| 双替换，两个 Swift 的动量权重归零 | −90.07% | −16.09% |
| 双替换，仅 standard 启用 single_entry | **−59.12%** | +37.38% |

限制 standard 持续加减仓，在六个世界的配对均值上全部改善，平均 **+17.80 个百分点**，但它仍只有 1/12 局盈利。该开关同时改变补仓、减仓、部分退出以及实际风险敞口，不能把全部改善狭义归于“禁止摊平”。early-single 参数没有变化，其最后一行变化来自交互和撮合路径，不是自身参数改进。

深度归零的均值改善主要由少数世界拉动：standard 仅 2/6 世界改善，early-single 仅 1/6。动量归零在少数世界损失了很大的盈利机会，平均更差。现有证据不支持“删除一个坏指标就解决”。新批次 early-single 双替换均值为正，但中位数 **−37.37%**、仅 **3/12** 局盈利，仍不能叫稳定生存。

## 排除了哪些解释

- **并非主要是追入停息垃圾股。** 新环境两个账户分别 99.14%、98.96% 的买入金额发生在当前分红仍高于初始 25% 时。该分类不意味着公司未来安全，只说明亏损不能简单归因于买入时已停息。
- **并非主要是完全卖不出去。** 新环境有持仓的股票观察中，买盘缺失仅占 standard 约 0.02%、early-single 约 0.01%。首次买入的成交量/请求量反而上升；进场不一定更难，但成交后的价格更不利。这里没有排除较差卖价、部分成交和等待时间的影响。
- **缺卖盘确实影响机会选择，但不是唯一原因。** 有买入意向却因盘口缺边不能提交的比例，standard 从 12.01% 升至 17.93%，early-single 从 16.87% 升至 27.38%。能看到的正信号与真正能买到的机会不是同一集合。
- **盘口深度误读不是已证实的主因。** 实际买入时，必须依赖深度项才能超过入场阈值的金额份额约为 standard 3.95%、early-single 7.94%；持仓时深度项挡住退出阈值的观察也只有约 2%。对应消融没有稳定改善。
- **没有强平或代码失步解释。** 原独立组及本轮新增比赛两个 Swift 均无强平；只读 Probe 的 160,000 次决策重建与真实订单完全一致。新实验所有账户均零错误、禁用和跳过。

## 对后续开发的含义

这次实验暴露了两个不同问题，应该分别处理。

市场侧：Relay 名义上替换 Coral，但没有提供可持续的库存周转和相近的成交服务。先评估替代流动性是否真实存在、双方能否完成有经济意义的交易，不能只看账户数量或某个强 bot 收益下降。Value 的替换同样改变了需求和价格反馈。

Swift 侧：固定分数阈值没有适应信号收益的变化。后续可研究以已经到达的成交结果校准信号收益，比较预期收益与可执行买卖价差、费用和退出深度；设置更明确的首次开仓/后续追加条件，限制旧目标引发的反复调整。single_entry 只是有效的减损线索，尚不是合格修复。研究应继续用新世界验证，而不是把本轮记录反复调到盈利。

Horizon 信息优势与买入逆向选择的关系仍是待验证假说；本轮没有为了 Swift 的成绩修改其他账户的权限，也没有修改任何生产 bot。

新比赛共 **68 局、1,360 次守恒审计**。Windows 10 核共同亲和性预算、4 个市场线程，全部串行。8 局记录的模拟墙钟合计 37.665 s、CLI 40.548 s；60 局消融分别 191.971 s、209.415 s。记录影响多线程时序，记录批次是额外比赛，不能声称重放了原独立组。旧比赛与新增记录都未要求逐笔确定性。

参数效果先对同一世界的两次重复取均值，再按世界比较。JSON 中的 bootstrap 区间只作小样本描述；未对多项假说比较作显著性保证，也未据此挑选并部署赢家。报价诊断与对手归因是事后分析，未向策略提供未来信息。派生脚本额外检查成交数量、订单重建、对手匹配、现金与 FIFO 存量，避免把 post_fills 与下一轮收到的 fills 重复计入。
