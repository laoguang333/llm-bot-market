# 十倍资金挑战者：预先固定的研究口径

基线提交：`dfc685d`；采用当前 `scenarios/baseline-v6.toml`。挑战者另加一个账户，现金 200,000 元、每只股票 200 股，是普通账户现金及初始持股的十倍。按收益率排名，不能靠绝对盈利金额冒充打穿。

先使用普通消息权限。开发集为 26001–26020；验证集为 26101–26120；最终验收为默认 1001–1020 加未用于开发的 26201–26240。开发先比较十倍资金 Swift、NewsV2、Coral，再根据容量与风险设计新策略。验证或最终验收不达标时如继续修改，需要说明失败结果，并改用新的留出种子。

正式门槛沿用 CLI：平均排名百分位至少 90，且至少 80% 的局进入前 25%。市场质量与跳过决策、错误、停用另行报告。性能使用 release、4 个比赛线程，Windows 全流程共用 10 个逻辑核心上限，比赛串行。多线程成交路径不保证逐笔相同。

只有普通消息权限路线未达标后，才启用用户授权的“更可能提前收到新闻”对照。该优势须由市场消息投递层显式配置并记录，不得在 bot 内反推世界种子或读取隐藏事件；背景账户、新闻时间与区间精度保持原规则。优势结果与普通权限结果分开报告。

发布前补充：消息倍率也加入 `Start` 开局元数据，旧 JSON 默认倍率 1。策略不读取倍率来改变交易，只依据实际收到的消息。此前冻结 120 局保留为 `first-pass-*`，增加元数据后保持策略参数不变，复跑同一整套 120 局作为最终发布验收，不据此调参。
