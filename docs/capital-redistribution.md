# 开局资本再分配

`capital_redistribution` 是可选的场景配置，省略时保持原有行为。它用于保留背景账户的人数和策略，同时调整初始资产的集中度。不是盘中转账、收益补贴或亏损补偿。

```toml
[capital_redistribution]
from_bot = "grid"
cash_each = 2_000_000
shares_each = 100
recipients = { coral = 20, value = 20, hunter = 20, momentum = 20, shark = 20 }
```

金额单位为分，股数为每只股票的股数。上例先按 `[[bots]]` 的原始配置构造所有账户，再从每个匿名 Grid 账户取出 20,000 元、每只股票 100 股。若原始配置为 40,000 元和 120 股，实际开局就是 20,000 元和 20 股。`summary.json` 的 `initial_cash`、`initial_shares`、`initial_equity` 以及 bot 的 `Start` 均反映实际开局资产，收益率分母也使用这些资产。

池中资产按 `recipients` 的相对权重分到策略，然后在该策略所有匿名背景账户之间等分。权重为 1–1,000,000 的整数，不要求和为 100。每笔金额、每只股票分别用整数累计分摊，余数按策略名的排序及原账户顺序处理，最多存在一分或一股的同组分配差。源账户的逐股票覆盖值也必须足够支付转出股数。

显式指定 `owner` 的账户不参与取出或接收。追加的 `challenger`、Almanac/Osprey 等命名常驻账户维持原资金与权限。匿名同名策略可以有多个配置组，按实际抽中的总人数合并计算。

源与每个接收策略都必须至少有一个保证存在的匿名账户。源不能同时是接收者；资金不足、未知接收者、零权重、接收后超过账户金额或股数上限都会报错，不丢弃余数，也不悄悄少分。

## 边界与审查

实现位于 [capital.rs](../crates/market/src/capital.rs)。仅在初始化时运行一次，位于人数抽样后、世界和 bot 创建前。只读取场景配置与账户初始余额，不读取世界种子、新闻、未来价格或最终结果。账户顺序、bot 种子、参数、信息权限与决策频率不变，撮合、结算和消息投递代码不变。

总现金和每只股票总量不变，但不同策略得到的资产不同，会改变订单规模、库存决策、价格路径和收益；并不保证股息、费用、坏账或最终总财富一致。

测试覆盖变化人数的逐资产守恒、实际 Start/账本基数、命名挑战者隔离、小额余数、逐股覆盖、无效配置和接收方上限。完整 workspace 测试也覆盖既有撮合优先级、消息与守恒行为。开发与留出运行另外逐局检查总资产、新闻文件、信息投递、股息、终值和守恒审计；实验协议见 [资本分散实验](capital-v18-protocol.md)。
