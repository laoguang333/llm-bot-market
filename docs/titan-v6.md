# Titan：十倍资金与提前消息优势（2026-10-19）

**结论：同等消息权限的 Titan 尚未打穿；提高提前获知新闻的概率后，通过当前 v6 的正式排名门槛，并在另外 40 个新世界中再次通过。** 这是用户授权的信息优势实验，不是普通权限下的策略胜利，也不意味着任何世界都盈利。

当前 v6 的阵容和经济规则固定在提交 `dfc685d`。`baseline.toml`、`baseline-v6.toml`、`baseline-per-tick.toml` 未因本次挑战而改动，Titan 也没有加入背景阵容。每次比赛只额外加入一个挑战者：现金 **200,000 元**、每只股票 **200 股**，现金和初始持股均为普通账户的十倍；按收益率排名。seed 7 初始权益为 378,420 元。

## 策略如何交易

源码为 `crates/bots/src/titan.rs`，注册名 `titan`。它没有复制 Coral 的历史分位报价，也没有把十倍资金直接交给 Swift 的二元进出场规则。

1. **估算剩余现金流。** 使用当前股息、本人已收到的新闻区间交集及私人终值提示的中点，计算剩余普通股息和期末兑现。新闻的公开时间与生效时间分开处理，现金流从 `effective_tick` 起改变；不是收到新闻后立即把当前股息改掉。它不直接优化组合奖励，持仓配对产生的组合现金流仍正常结算。
2. **用近期市场价格校准估值。** 维护“盘口中价 / 现金流估值”的 150 tick 指数平均。新闻改变估值时，交易锚立即随之改变，而市场相对估值的习惯水平缓慢调整。这样既利用新闻，又不假设市场始终严格贴着模型价值成交。
3. **加入成交方向。** 20 tick 衰减的主动成交量差，按总量归一化到 −1～1，最多将报价锚向上或向下调整约 2%。没有单独的“大阳线必须出现”条件。
4. **按价格优势连续分配仓位。** 默认目标权重为 `clamp(12 × (交易锚/中价 − 1), 0, 0.45)`。全组合目标按比例缩到最多 2 倍权益，单次调仓约占权益 2.5%。目标不是一次性清仓/全仓开关，允许分批买入和卖出；报价、资金、可卖数量、行动次数都受游戏约束。
5. **根据价格优势选择主动或被动成交。** 买价不高于交易锚减 0.15%，卖价不低于交易锚加 0.15%。有足够优势时用 IOC，最多扫到距当时中价 0.5% 的价位；否则在自己的价值限制内改善盘口报价。已有委托先按需撤改，复用审查过的 `requote` 执行器。
6. **期末收敛。** 最后 400 ticks 逐渐撤掉历史市场溢价，靠本人合法推断的现金流估值收敛，避免因为市场曾经高估就一直用高估价格持仓。成交方向项仍存在，不声称终值完全已知。

这条路线的容量来自持续调仓和有限扫档，信息优势则来自更早识别股息路径的变化。它仍会受到盘口深度、库存、噪声新闻区间、未知后续新闻和期末估计误差的限制。

## 信息优势的准确含义

账户组新增 `news_multiplier`，默认 **1.0**。CLI 的挑战者可通过 `--news-multiplier` 单独指定；不会继承背景第一组的特殊权限。每阶段累积获知概率为 `min(原概率 × multiplier, 1)`，继续使用同一“事件×账户”的随机抽样值，不重新抽世界。`Start.news_multiplier` 向本人公开这一配置，`Rules.news_stages` 保留基础概率；旧 Start JSON 缺少字段时按 1.0 读取。Titan 不依赖倍率数值选参数，只依据实际收到的消息交易。

| 相对新闻首次披露 | 普通账户 | 本次 Titan（倍率 10） | 信息精度 |
|---|---:|---:|---|
| 0 ticks | 5% | 50% | 原规则的宽区间 |
| 30 ticks | 累积 25% | 累积 100% | 原规则的较窄区间 |
| 60 ticks | 100% | 100% | 同时公开精确变化 |
| 120 ticks | 股息实际改变 | 股息实际改变 | 生效时点相同 |

这里只增加获知概率：不提前到首次披露之前，不改变新闻冲击，不给更窄的区间，不提前给终值答案。背景账户权限和抽样结果不变。40 个留出世界中，Titan 平均第一阶段收到 51.775 个事件，普通权限为 4.95 个。每局 `summary.json` 记录 `news_multiplier` 和 `news_received_by_stage`；后者是各阶段的消息更新次数，同一个事件可在多个阶段计入。

代码审查覆盖 Titan、Knowledge、hold_value、requote 及新增投递路径：策略只读公开规则、本人账户和已交付观察，不访问隐藏世界、不反推种子、不读取其他账户身份、不读文件或调用网络。测试还验证改变 Start.seed 和账户身份不会改变同一观察下的决策；已收到新闻可以在生效前改变交易目标。

## 利润来源和市场质量

额外 40 世界按每局初始权益归一化后的平均贡献如下。残差包含交易与期末库存估值，不等于已经逐笔平仓实现的价差收益。

| 贡献 | 普通权限 | 增强权限 |
|---|---:|---:|
| 交易、期末库存等残差 | −8.18% | +55.86% |
| 普通股息 | +68.63% | +113.38% |
| 组合现金流 | +1.74% | +3.31% |
| 交易费 | −2.49% | −3.85% |
| 闲置费 | −14.60% | −18.56% |
| 利息 | −2.63% | −4.01% |
| 总收益 | +42.47% | +146.14% |

因此不是“全部靠价差盈利”，也不能只从股息大就断定新闻策略无效。信息优势改变了买卖时机、持有的股票与持有时长；配对实验支持它对总收益有明显影响，尚未把这几个渠道逐一拆开。当前游戏仍采用用户选择的个人时钟逐 tick 分红和整仓舍入，此实验没有改动或重新证明该机制的全部性质。

排名通过与市场质量分开报告：默认正式组质量全项通过 **15/20**，另外 5 局仅价值穿越次数不足；额外留出优势组为 **29/40**，失败项为价值穿越 6 次、估值偏离 5 次。同批普通权限为 **35/40**，失败项为价值穿越 3 次、估值偏离 2 次。没有修改质量阈值，不能把排名打穿写成所有市场指标通过。

冻结后的 120 局（优势验证 20＋正式 20＋留出 40＋普通对照 40）全账户零跳过决策、零 bot 错误、零停用；挑战者零拒单、零强平，每局 3000 次决策、6 次引擎审计。正式及留出组 Titan 每次决策平均约 3.0 微秒，明显低于 2000 微秒预算。

## 引擎兼容性与性能

新增权限只影响开局生成指定账户的新闻投递列表，不改变撮合优先级、现金/股份结算和调度频率。普通权限下，改动前后 release 在种子 7/11/19、单线程完整 3000 ticks 的成交 CSV 和账户结算逐项完全相同。工作区 99 项 Rust 测试及严格 Clippy 通过，包括撮合、邮箱、守恒、消息时点和本次权限隔离测试。

性能比较使用当前 v6，无挑战者，种子 7/11/19，4 线程、全流程 Windows 10 核预算；两个版本各预热一次、交替串行运行。终版第一批每种子重复 3 次，进程墙钟中位数 **1.353 → 1.447 秒（+6.9%）**，单次配对变化有正有负。为核对这项波动，再单独串行运行每种子 5 次：墙钟 **1.311 → 1.340 秒（+2.2%，约 29 毫秒）**，引擎中位数 **1.203 → 1.233 秒**。结论是复核中有小幅变慢，不能宣称零开销；多线程行情路径和墙钟波动仍存在，不能把整个差异都确定归因于消息投递。两批数据均保留在[完整检查](titan-engine-checks.json)中，没有挑掉较慢的第一批。
