# v12：Horizon v3 正式进入基准

> 归档记录：当前默认已升级至 [v13](baseline-v13.md)。以下配置、别名与验证描述对应 v12 晋级时；`baseline-v12.toml` 保留不变。

按用户选择，将已完成固定参数研究的 Horizon v3 纳入正式背景。`scenarios/baseline.toml` 与 `scenarios/baseline-v12.toml` 相同。新版接替 v11 原 Horizon 的账户，名称仍为 `horizon-incumbent`；人数、初始现金和股票供给不增加。

| 项目 | v12 Horizon |
|---|---|
| 策略 | `horizon`，已审查的 v3 |
| 初始资金 | 现金 20 万元、每股 200 股，与 Titan 相同 |
| 普通消息倍率 | 1 |
| 额外研究 | 最大提前 1000 ticks、覆盖率 50%、区间宽度 3 倍标准差 |
| 仓位与执行 | 目标杠杆上限 2、单股权益权重上限 45%、每次切片 2.5% |
| 研究计划 | 开启，保留分批建仓与后续额度预留 |
| 期末风控 | 开启保守兑现资产与债务比较 |
| 费用 | 全部照常收取 |

场景显式写出经过验证的六项策略参数，避免以后修改默认参数时悄悄改变此版本。实现和源码哈希对应 [Horizon v3 研究](horizon-v3.md)，本次没有修改 bot 或引擎代码。

总计 **100–224 个账户、13 种策略**，seed 7 为 148 个。保留标准 Swift、小资金单次入场 Swift、NewsV2、普通权限 Titan，以及其余原有背景策略。v11 的旧 Horizon 不再同时出现在 v12 中；旧版本、历史研究场景及录制仍可查看。

对局仍为 10000 ticks，新闻生成、分阶段成长者、股息、组合收益、期末兑现、收费、撮合和调度规则沿用。Horizon 的研究方式及收报提前量改变了，持仓、成交、价格和排名会随之变化；每 tick 决策不等于每 tick 必须成交。

上轮研究发现远期策略可能使成交连续性变差。供需在高频决策下较快达到暂时平衡、外生交易需求不足，是待验证的解释；本次不把这一猜想当成已确认原因，也不新增强制交易或修改市场质量门槛。

## 晋级核验

使用上一轮已经审查、测试并冻结的 release 程序，先核对当前 Rust 源码及二进制哈希；场景结构检查只允许替换 Horizon 策略、研究提前量及固定参数，其他账户和世界配置一致。Windows 共用半机 10 核预算、4 工作线程；种子 7、27006、28012，各三次，交错串行运行 v11/v12，另各预热一次。

共 20 局（18 局计时、2 局预热），400 次守恒审计通过，bot 错误、禁用与跳过决策均为零。九对比赛的账户初始现金、股份、权益，以及外生新闻、最终股息和终值抽签均一致。

| 场景 | 进程墙钟中位数 | 范围 | 引擎中位数 | Horizon 平均单次决策 |
|---|---:|---:|---:|---:|
| v11 | 5.136 秒 | 4.546–5.319 秒 | 4.623 秒 | 7.93 微秒 |
| v12 | 5.048 秒 | 4.543–5.407 秒 | 4.631 秒 | 13.91 微秒 |

整体耗时接近，不能把小幅差异宣称为加速；Horizon v3 自身计算量增加，但没有降低决策频率。原市场质量全项通过数为 v11 的 6/9 与 v12 的 7/9，仅三个重复世界，不能推翻上一轮跨世界观察到的成交连续性问题。

机器汇总为 [baseline-v12-results.json](baseline-v12-results.json)，原始输出在 `runs/v12-validation/`。这只是三个世界的晋级回归和性能核验，不是新一轮 40 世界策略验收；旧研究收益不移作新基准成绩。

运行当前基准：

```text
target/release/llm-market.exe run scenarios/baseline.toml --out runs/v12-example --seed 7 --threads 4
```

`tools/validate_v12.py` 保存对照及哈希，须经 `tools/arena_gate.py` 串行运行，已有输出拒绝覆盖。未来若再改 Horizon 实现，需要保存本版源码并固定历史策略调用，不能让 `horizon` 注册名的升级静默改变 v12 的历史含义。
