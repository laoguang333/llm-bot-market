## 策略与行为影响

输入限于公开规则、收到的新闻和私人终值区间、公开盘口和匿名成交，以及自己的账户。代码不使用 `Start.seed`、账户身份、其他账户状态、外部文件或隐藏世界数据。挑战配置为现金 **2,000,000 分（2 万元）**、每只股票 **20 股**、新闻倍率 **1**、额外研究 horizon **0**，正常支付交易费、闲置费和融资利息。初始总权益还包括股票，不能把 2 万元当成收益率分母。

1. 把已投递新闻按实际生效时点排列，计算预计剩余股息及期末价值；相同事件的后续消息收窄区间，生效后移出预测，避免重复计价。同一时点的变化先合并，派息估计按公开下限取值。
2. 用市场价格与该估值的历史比值校准估值，结合近 20 tick 成交方向和相对 60 tick 均价的动量形成目标仓位。未知新闻和增长路径仍然未知，没有从世界种子推演未来。
3. 分别按实际买一、卖一计算目标仓位，把手续费及额外边际计入买卖阈值。使用最优一档价格的限价 IOC；成交不足可以下次重试，不沿更差档位扫单，也不遗留被动挂单。
4. 所有买单共用含费用的预算；卖单不超过可售股份。默认总杠杆目标 1.8、单股权重上限 0.55、单次调整上限为权益的 8%。行情变化可能使实际杠杆短暂超过目标。超过目标的 1.12 倍，或后期负债超过保守终值资产的 70%，暂停新买入并逐步减仓。
5. 最后 500 ticks，市场比值锚和短期成交信号逐渐让位于终值估计。负债检查从最后 `max(全局时长×10%, 400)` ticks 开始。

策略试图利用已知消息与市场价格反应之间的差异，并用成交方向和价格动量调整仓位；持仓期间另有实际股息收入。这是交易依据和设计假设，尚未通过消融实验证明各信号对盈利的因果贡献。买卖缓冲区减少小幅波动下的反复换手；代价是可能错过短暂机会，最优价 IOC 在流动性不足时会部分成交或不成交。普通权限不等于无杠杆，策略仍会融资并承担价格及终值风险。策略每个 tick 都作决策；没有通过降低决策频率优化系统性能。

默认参数：`horizon=180, gain=14, cap=0.55, leverage=1.8, flow=0.025, momentum=0.3, edge=0.002, clip=0.08, base=0`。未针对留出集调参。

## 追涨杀跌群体与收益解释

本次使用含 `profit_effect` 的 v13，配置人数 9–21，40 个留出世界实际为 9–20 人，没有漏掉这一群体。成员参考组内和自身近期盈亏及简单价格变化，负向信号放大；少数成员额外偏好上涨领先的两只股票。因此可能出现上涨吸引买入、盈利经历再吸引同伴，以及亏损推动减仓的反馈。群体的具体规则见 [领涨研究](profit-effect-leaders.md)。

Kestrel 本身也有跟随买压和上涨动量的成分，但不读取该群体的私人盈亏分享、不识别成交者身份，也没有单独估计“追涨群体强度”。它看到的是所有参与者共同形成的匿名成交和价格。离期末较远时，成交方向与动量的估值乘数为 `1 + 0.025 × flow + 0.3 × momentum`；flow 为 20 ticks 指数衰减的主动买卖成交量差／总量，momentum 为中间价相对 60 ticks 指数均价的偏离（截断到 ±5%）。例如 flow=0.6、momentum=2%，该乘数为 1.021；是否下单还取决于新闻估值、市场比值锚、价差、费用和已有仓位。

离线账本显示，40 局合计与 ProfitEffect 直接成交的金额占 Kestrel 总成交额 **2.59%**。这不是利润占比，也不能排除他们通过价格和其他对手产生的间接影响。现有结果不能证明 Kestrel 的利润主要来自该群体；需要保持人口和资金等条件的群体行为对照，才能进一步检验。

将每局账目除以该局初始总权益，再对 40 个世界等权平均，得到以下会计拆分：

| 项目 | 对净收益的贡献 |
|---|---:|
| 交易、库存及期末兑现合并残差 | +550.11 个百分点 |
| 普通股息 | +326.69 个百分点 |
| 组合收益 | +3.36 个百分点 |
| 交易手续费 | −54.32 个百分点 |
| 闲置费 | −187.15 个百分点 |
| 融资利息 | −27.03 个百分点 |
| **最终净收益** | **+611.67%** |

这是账目恒等式，不是把“新闻”“动量”“追涨群体”的贡献分开。残差包含买卖、初始持股到期末兑现的变化；因为表中单列了全部闲置费，还加回了按计费时标记价记录的股份扣款，不能称作纯已实现交易利润。股息收入的贡献也不能解释为“关闭股息后净收益恰好减少 326.69 个百分点”，因为交易、仓位和复投路径会随之变化。上述字段已纳入 `tools/report_kestrel.py` 的可复核汇总；没有为本节重新比赛或调整参数。

## 验收协议

先完成主代理自行审查及 6 项 Kestrel release 测试，再运行开发种子 1–8。审查不是独立子代理审查；记录在 `runs/kestrel/pre-run-review.json`。背景策略沿用仓库已有的审查版本。

开发集通过后，在首次运行留出集之前冻结源代码、二进制和基准场景 SHA-256；记录在 `runs/kestrel/freeze.json`。标准留出集为 **1001–1020**，额外确认集为 **43001–43020**。两个集合各 20 个世界，每个种子重复 **1** 次，参数完全一致。通过条件沿用 CLI：平均排名百分位 **≥90** 且前 25% 占比 **≥80%**。

全部使用普通 release 构建，**4 个市场工作线程**。Windows 20 个逻辑核心中，Python 包装进程及子进程的亲和性限定为 **10 核**；构建、测试、比赛串行，比赛通过 `arena_gate.py` 避免与同仓库实验竞争。多线程逐笔执行顺序不保证复现，结果属于这些抽样世界；不能外推为所有世界、资金规模或新版本基准都能通过。

## 复现

```sh
python tools/build_release.py
python tools/arena_gate.py --cwd . -- python tools/bench_bot.py kestrel-replay-holdout --bot kestrel --scenario scenarios/baseline-v13.toml --first-seed 1001 --seeds 20 --threads 4
python tools/arena_gate.py --cwd . -- python tools/bench_bot.py kestrel-replay-confirm --bot kestrel --scenario scenarios/baseline-v13.toml --first-seed 43001 --seeds 20 --threads 4
```

`bench_bot.py` 要求新的输出目录名。每次运行保存精确命令、所有 Rust 源码和场景哈希、二进制哈希、逐局 summary、成交记录及 `challenge.json`。无需修改基准或给挑战者增加权限。

本次原始目录是 `runs/bench/kestrel-dev-1`、`runs/bench/kestrel-holdout`、`runs/bench/kestrel-confirm`。保留这些目录及冻结文件后，运行 `python tools/report_kestrel.py` 会重新核对普通权限、资金、逐局分数和完整源码哈希，并生成本报告的 JSON 数据；它不运行比赛、不选择参数。
