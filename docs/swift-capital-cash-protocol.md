# 追加机制核验：大额现金是否需要大额开局股票

这是主矩阵 A 批完成后提出的追加问题，不冒充原矩阵开始前的假设。A 批 300 倍权益下，卖出初始股票的 cash 对照也显著压低 Swift 的收益，因此必须区分新增现金购买力与直接获得大量初始库存。主矩阵 B 批、原定独立确认的计划不变。

## 固定设计

沿用原版 Swift、v5 背景和全部费用。选择已有信号反馈 relay，不优化信号或阈值。对手总权益为 Swift 的 100 或 300 倍，在每个倍率比较：

1. relay-scaled：初始股票、固定交易额度、每次股数均按倍率增加，与主矩阵相同。
2. relay-cash_active：初始仍为每只股票 200 股，其余总权益为现金；固定交易额度为全部初始权益，单次股数与 scaled 相同（100 倍为 400 股，300 倍为 1,200 股）。需要额外库存时必须真实买入，不借用目标或背景账户股票。
3. cash-scaled：同 scaled 的初始资产，尝试卖出后持现金。
4. cash-reserve：同 cash_active 的初始资产，尝试卖出后持现金。

八个配置各交换两次顺序，在新种子 17001–17020 运行，共 320 局；另加 20 局 Swift 单独参赛，共 340 局。两种顺序按种子聚类，不能称为 40 个独立市场。除必要的固定每次股数参数及开局资产配置外，不修改旧策略行为。旧矩阵和确认批次全部结束后再更新代码，保留原有冻结二进制与提交。

主要比较是 cash_active 减 scaled 的 Swift 收益、狩猎者收益与绝对损益；两者也分别与同资产的现金对照比较。报告 Swift 亏损概率、双方收益率差、双方都亏时狩猎者少亏、直接成交、换手和费用。不同初始库存本来就会改变市场路径，不能当作固定价格回放。

这组用于回答只新增现金并允许充分使用是否也能达到目标；无论结果如何都完整保留，不再根据该组结果调节参数或增加资金档位。
