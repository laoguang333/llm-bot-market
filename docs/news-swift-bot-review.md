# 运行前审查：News 与订单流机制（2026-10-19）

**后续采用记录：** 当前 v6 已按用户决定用 NewsV2 等额替换旧 News 组。本次替换前重新审查 `news_v2.rs` 和 `news.rs` 的 Events helper，确认信息边界、最优价 IOC 与共享预算保持原实现；默认策略没有修改。新的运行、测试、哈希和 18 局检查见[当前基准](baseline-v6-current.md)与[验证数据](baseline-v6-news-v2-validation.json)。以下“背景仍用旧 News”仅描述原始研究批次。

基准策略沿用正式 v6 的已审查实现。当前工作区中的引擎、旧 News、Swift 与场景不因本轮研究修改。

- `news.rs`：只累计 Observation 已投递的新闻。按 (事件 id、股票) 维护区间交集，公开时刻来自已收到的 NewsItem；使用该已知日程撤销目标是允许的。没有获取未投递的内容。NewsFixed 以实际账户持股对齐净目标，未成交不记为仓位；同股票重叠事件按目标净额处理，不伪称精确分配每条事件的逐笔利润。共用购买预算、动作上限及可售股数，不卖空。
- `news_v2.rs`：复用 Swift 的交易信号/执行逻辑，加已收到的新闻方向偏置；范围不确定性降低权重，公开后衰减。没有读取世界种子、其他账户、外部文件、网络或世界生成器。新闻权重为零与原 Swift 逐步订单一致，由测试覆盖。默认权重在观察本轮收益前确定。
- `flow-eval.rs`：只是研究 harness，正常模式逐字传递当前观察。随机/反转方向保留成交时间、价格、数量和顺序；随机流使用固定独立常量，不解世界种子。大阳线代理只读取该挑战者过去和当前报价。仅买入过滤的实验保留全部卖出动作。研究干预明确标注为实验，不冒充原版 Swift。只有挑战者套用 wrapper，其他账户和撮合不改。
- 赛后 CSV 可以含全体成交/新闻真值，由既有报告器输出；这些仅供离线分析，不回送策略。本轮没在引擎中加入研究分支。

功能测试覆盖：多股票新闻、连续未成交重试、公开后按实际增仓减仓、部分退出重试、重复投递/事件重叠净额、资金和动作预算、负事件不能卖空、新闻偏置能改变决策且不依种子、零偏置与原 Swift 一致，以及研究方向变换/30 tick 价格窗口。已通过全工作区严格 Clippy 和测试；release 构建完成后冻结源文件和二进制再运行。

行为影响：新策略通过新增名字 `news_fixed` / `news_v2` 使用，正式 v6 仍引用旧 `news`。NewsFixed 的完整退出、多股票参与、最优价成交和共享预算都会改变旧版表现，不能把总差异全部归给一个 bug；NewsV2 进一步改用持续订单流与新闻组合，需与修复版及 Swift 分别比较。
