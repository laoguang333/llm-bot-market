# v13：赚钱／亏钱效应群体正式进入基准

按用户选择，把已经完成研究的 `profit_effect` 纳入正式背景。默认 `scenarios/baseline.toml` 与 `scenarios/baseline-v13.toml` 相同；旧 v12 与独立研究场景保留。此次晋级没有修改 bot 实现或引擎规则，也不要求新增挑战者打穿基准。

## 阵容

总人数区间仍是 **100–224 个账户**，策略数从 13 增至 **14 种**。原 Noise 的 18–42 人区间调整为 9–21 人，另加入 9–21 个收益效应成员。原有 grid、value、momentum、NewsV2、hold、hunter、shark、tracker、Coral、两个 Swift、普通权限十倍 Titan 和 Horizon v3 保留。

| 群体成员 | 每局人数区间 | 额外领涨权重 | 自动账户名预留范围 |
|---|---:|---:|---|
| 普通成员 | 6–14 | 0 | `profit_effect#0` 至 `#13` |
| 较轻追涨 | 1–3 | 0.5 | `profit_effect#14` 至 `#16` |
| 中等追涨 | 1–2 | 0.8 | `profit_effect#17` 至 `#18` |
| 较强追涨 | 1–2 | 1.1 | `profit_effect#19` 至 `#20` |

每个成员现金 **20,000 元、每只股票 20 股**，沿用普通账户的资金配置，正常支付所有费用。组内和自身的实际盈亏、原有简单价格变化权重都保留；只有后三组额外追近期上涨领先的两只股票。领涨门槛 0.5%，单股上限 30%，单次订单约 2% 权益，追价边界 3%，仅用可用现金。敏感度、同伴／自身／原价格权重等既有个体差异继续保留。

四组共享一个 `profit-circle`：只收到本组其他成员的近期实际盈亏均值，不含自己重复计数，不含其他策略账户的私有数据。浮盈、费用及到账股息照实记录，不传未来信息；bot 不读估值或新闻内容。所有成员普通新闻倍率为 1，无额外研究权限。

**人数按组独立抽样，领涨者比例不是每局严格三分之一。** 相比 v12，人数范围和人均初始资产配置相同，但单个种子的人数、市场总现金与股份可能改变，不能说每个世界都做了等资金替换。研究阶段为控制变量而冻结人口的 80 局，对应 [领涨研究](profit-effect-leaders.md)，不能直接改称 v13 的成绩。

| 种子 | v12 总人数 | v13 总人数 | 收益效应成员 | 其中领涨成员 |
|---|---:|---:|---:|---:|
| 7 | 148 | 160 | 17 | 3 |
| 27006 | 180 | 175 | 19 | 5 |
| 28012 | 168 | 183 | 20 | 6 |

10000 ticks、三层新闻、分阶段成长者、Horizon v3 的 1000-tick 研究权限、股息、组合收益、期末兑现、闲置费、撮合和调度全部沿用 v12。每 tick 决策不等于强制成交。

## 行为影响与晋级核验

此前固定人口研究显示，少数追涨成员能使其余组员持续交易；但跟随者可能更加活跃而亏得更多，部分冷门股票的成交连续性也可能变差。加入基准是增加行为类型，不是认证这个群体能盈利。没有据此放宽市场质量门槛或重新调参。

本次使用上一轮审查、测试并冻结的 release 程序，核对源码和二进制哈希，检查场景只调整 Noise 人数区间和新增上述四组。再次通过 **144 项 Rust release 测试**、调试器 JavaScript 语法检查及消息关联测试。

Windows 半机 **10 核**预算、**4 工作线程**；种子 **7、27006、28012，各重复 3 次**，交替顺序串行比较 v12/v13，另各预热一次。20 局合计 **400 次守恒审计通过**，0 bot 错误、0 禁用、0 跳过决策。每局账户数、命名及初始现金和股份都与配置抽样一致；九对比赛的外生新闻、最终股息及期末兑现抽签一致。人口和市场资金差异如上表，不做等资金收益归因。

| 场景 | 墙钟中位数 | 范围 | 市场质量全项通过 |
|---|---:|---:|---:|
| v12 | 5.003 秒 | 4.603–5.398 秒 | 6/9 |
| v13 | 5.031 秒 | 4.645–6.087 秒 | 4/9 |

中位数约增加 **0.55%**。这是包含人口、成交行为改变的整局耗时，不是排名或分享计算的单独微基准。质量通过率没有改善；这里只有三个独立世界，重复运行不能算九个不同世界。本次不据此给出新策略收益结论。

机器报告见 [baseline-v13-results.json](baseline-v13-results.json)，原始记录位于 `runs/v13-validation/`。`tools/validate_v13.py` 保存场景、源码和二进制哈希，核对上述条件并拒绝覆盖旧输出；它引用本机上轮的已审查冻结程序。

## 运行

```text
python tools/build_release.py
target/release/llm-market.exe run scenarios/baseline.toml --out runs/v13-example --seed 7 --threads 4
```

当前复盘工具能显示 ProfitEffect 的组内盈亏、自身盈亏、领涨名次及加分、目标与实际仓位、进出场连线。新录制可选择始终存在的 `profit_effect#14`（较轻追涨）和 `profit_effect#0`（无额外领涨权重）。历史录制保持原场景信息，不随默认基准升级重写。
